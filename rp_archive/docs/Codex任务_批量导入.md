# Codex 任务：探索踩点「文本批量导入 / 导出」

一个个点太麻烦。给探索后台加：**用一段文本一次性导入地点和掉落（线索、物品、数量、权重），也能一键导出成同样格式。** 另外次数也能用文本批量设。

**分工与边界（这次你要同时做后端和前端）**

| 内容 | 谁 | 文件 |
|---|---|---|
| 文本解析 + 校验（纯函数，可单测） | 你 | **新建** `rp_archive/explore_import.py` |
| 三个新接口（预览/导入、导出、次数导入） | 你 | `rp_archive/explore.py`，**只许新增函数和在 `register()` 里新增路由**，不许改已有函数的行为 |
| 后台界面 | 你 | `rp_archive/templates/explore_admin.html`、`rp_archive/static/explore.css`、`rp_archive/static/explore.js` |
| 测试 | 你 | **新建** `rp_archive/tests/explore_import_test.py`（并让 `run_all.sh` 能自动跑到它，它按文件名匹配的话就不用改） |

**不许改**：`app.py`、`explore.py` 里已有函数、`tests/explore_test.py`、玩家端（`explore.html`）、任何小手机文件、插件 js。不要部署，不要 git commit。

**已定的设计决定（不要改）**

1. **地图上的位置仍然在线上设计**（后台图上点选）。导入只管地点的名字、图标、描述和掉落表。
2. 文本里的地点**可以带 `x=` `y=`（0~100 的百分比）**；不带的话：
   - 新建的地点一律创建为 **停用**（`enabled=0`），玩家端看不到，也不会被踩到；位置先填 50/50。
   - 后台「地点与掉落」里这类地点要有明显的「待定位」标记；管理员在图上点选位置并打开「启用」后才对玩家可见。
   - 带了 `x=` `y=` 的新地点按文本里的位置创建并**启用**。
3. 物品**必须是注册物品**：复用后端现有的校验方式（`_admin_grant_item_names(db, sid)` 给出的名字集合，和 `explore.py` 里 `admin_spot_save` 校验物品用的是同一份）。不认识的名字就是错误，不许放行。
4. **整体原子**：预览发现任何错误，则「导入」按钮不可用、接口拒绝写入；全部通过才一次性写库（单事务）。
5. **同名处理**：同一张地图里已有同名地点时，必须由管理员选 `skip`（跳过，默认）或 `replace`（只覆盖这个地点的描述、图标、掉落表；**保留它现在的位置和启用状态**，除非文本里明确带了 `x=` `y=`）。**绝不能默认覆盖。**
6. 掉落条目的 `id`：导入 `replace` 时，如果某条线索的「标题」和旧表里某条线索标题相同，**沿用旧条目的 `id`**（玩家已经拿过的线索才不会被重复发放）；标题不同则生成新 `id`。物品、空手条目生成新 `id` 即可。

## 文本格式（权威定义）

```
# 地图：学院
@图书馆 📚 x=20 y=28 | 安静得能听见翻页声。
线索 5 | 撕碎的信 | 信纸被撕成两半，只剩半句：「别让他知道……」
线索 3 | 借阅卡 | 最后一张借阅卡，签名被人刻意涂掉了。
物品 2 | 钥匙 ×1
物品 1 | 旧地图 ×3 | 压在书页里的一张泛黄地图。
空手 2 | 只有灰尘。

@钟楼 🔔 | 整点的钟声，听久了会数错。
线索 4 | 停摆的怀表 | 怀表停在 21:07，表盖内侧刻着 L.W.
空手 3
```

### 语法

- **空行**可有可无；`//` 开头的行是注释，忽略。
- **地图行**：`# 地图：名字`（冒号全角半角都认）。之后的地点都属于这张地图，直到下一个地图行。**第一个地点之前必须先有地图行**，否则报错。地图不存在会**自动新建**（无背景图，管理员稍后再传）；已存在就复用。
- **地点行**：`@地点名 [图标] [x=数字] [y=数字] [| 描述]`
  - 地点名 ≤ 30 字；图标是一个 emoji（≤ 8 字符），可省略（默认 📍）；`x`、`y` 要么都写要么都不写，范围 0~100，可以是小数；描述 ≤ 200 字，可省略。
  - 管理员可能写 `｜`（全角竖线），要和 `|` 一样处理。
- **掉落行**属于上一个地点（地点行之前出现掉落行报错）：
  - `线索 [权重] | 标题 | 内容` — 标题 ≤ 30 字，内容 ≤ 600 字。内容里想换行写 `\n`（两个字符），解析时转成真换行。
  - `物品 [权重] | 物品名 ×数量 [| 掉落时显示的一句话]` — 数量 1~999，省略默认 1；`×`、`x`、`X`、`*` 都认；物品名可能含空格但不含 `|`。
  - `空手 [权重] [| 一句话]` — 权重后面可以什么都不写。
  - **权重**是紧跟在类型后面的整数 1~1000，省略默认 1。
  - 类型词认 `线索`/`物品`/`空手`，也要容忍写成 `clue`/`item`/`nothing`，全角空格、行首行尾空白。
- 一个地点最多 30 条掉落（和现有限制一致）；一次导入最多 60 个地点。
- 文本整体 ≤ 200KB。

### 错误信息要具体、带行号

`第 12 行：「钥匙」不是注册物品，请从后台物品下拉里确认名字`、`第 5 行：权重要在 1~1000`、`第 3 行：线索要有标题和内容`、`第 7 行：x 和 y 要同时填写`、`第 2 行：还没有地图行就出现了地点` ……预览要一次性给出**全部**错误（最多先给前 50 条），不要遇到第一个错误就停。

### 导出格式要求
- 与导入语法完全一致，**导出的文本再导入必须得到相同配置**（测试里要有这个往返用例）。
- 地点位置总是带 `x=` `y=`（保留一位小数）；停用的地点在行尾加注释 `// 停用`（解析时忽略注释，所以往返时停用状态不会被恢复——这是已知取舍，在界面上提示即可）。
- 线索内容里的真换行导出成 `\n`；内容里本来就含 `|` 的要保证往返安全（导出时把 `|` 换成全角 `｜`，导入把 `｜` 当 `|`，所以内容里的 `|` 会变成 `｜`，这个取舍在界面上提示一句）。

## 接口（都在 `explore.py` 的 `register()` 里新增，都要 `adm(...)` 包装并走 `_admin_guard()` 的 CSRF 校验；响应格式 `{ok, ...}`，和现有接口一致）

| 路径 | 方法 | body / 返回 |
|---|---|---|
| `/admin/explore/api/import` | POST | body `{text, mode: "preview"\|"commit", on_conflict: "skip"\|"replace"}` |
| `/admin/explore/api/export` | GET | 返回 `{ok, text}`；可选 `?map_id=` 只导出一张地图，默认全部 |
| `/admin/explore/api/quota_import` | POST | body `{text, mode: "preview"\|"commit"}` |

**import 的返回**
```
{ok:true, errors:[{line,msg}], plan:[{map, map_new:bool, spot, action:"create"|"replace"|"skip", has_pos:bool, drops:int, items:["钥匙×1",…]}],
 summary:{maps_new, spots_create, spots_replace, spots_skip, drops_total}, committed:bool}
```
- `mode=preview`：不写任何数据，`committed:false`。有错误时 `ok:true` 但 `errors` 非空（这是正常的预览结果）。
- `mode=commit`：先解析，**有任何错误则不写，返回 `ok:false, error:"有 N 处错误，请先修改", errors`**；无错误则在单事务内写入并返回 `committed:true`。
- `commit` 之后 `plan` 里 `skip` 的地点不动，`replace` 的按上面规则只覆盖描述/图标/掉落表。
- 掉落表写入前复用 `explore._clean_drops(raw, allowed_items)` 做最终清洗，保证和手动保存同一套规则。

**次数文本格式**（`quota_import`）：每行 `角色名 数字`（空格、Tab、全角空格、冒号都当分隔；数字 0~99），可选 `默认 数字` 这一行设置「默认每人每天次数」。角色名必须是 `_admin_role_list` 里存在的，否则这行报错。同一个角色出现多次以最后一次为准并给一条警告（放 `warnings`，不算错误）。返回 `{ok, errors, warnings, plan:[{role, daily, change:"自定义"|"同默认"}], committed}`。数字与默认次数相同的角色**不要**写成「自定义」，应删除其自定义记录（和现有「恢复默认」一致）。

## 界面（`explore_admin.html`，沿用该页面现有的风格和组件）

- 在「地点与掉落」块里加一个**折叠的「批量导入」面板**（默认收起）：
  - 一个大的等宽文本框（`textarea`，至少 12 行，手机上也能舒服输入；`spellcheck=false`）；
  - 下面一排：「示例」（把上面的示例文本填进文本框，覆盖前先确认）、「导出当前配置」（调 export，把文本填进文本框并可一键复制）、「预览」、「导入」；
  - 同名地点的处理：单选「跳过已有同名地点（默认）/ 覆盖它们的掉落表」；选「覆盖」时旁边要有一行醒目的小提示：「会替换这些地点现有的掉落表（位置和启用状态保留）」；
  - 预览结果区：先显示汇总（新增地图 N · 新建地点 N · 覆盖 N · 跳过 N · 共 N 条掉落），再逐地点列出计划（新建/覆盖/跳过的徽标、掉落条数、物品清单、「待定位」标记）；有错误时只显示错误列表（带行号，点一条能让文本框滚到并选中那一行），此时「导入」置灰；
  - 「导入」成功后：提示结果，刷新页面里的地图/地点数据（重新拉 state），并滚到「待定位」的新地点上方的提示：「这 N 个地点还没有位置，请在图上点选位置并启用」。
  - 对格式的说明收进一个「格式说明」折叠块（简短，列语法和 3 个小例子即可）。
- 在「次数」块里加一个小的折叠「批量设置次数」，同样「预览 / 应用」两步。
- 「地点列表」里的停用且从未定位过的地点（`has_pos` 为假，或 x/y 恰好 50/50 且停用）要显示「待定位」徽标；这个判断只是前端提示，用现有 state 数据即可，**不要为此新增数据库字段**。
- 所有按钮在请求中禁用；错误和成功都有明确反馈，不要只用 `alert`。
- 手机宽度（375）下面板、文本框、预览列表都不能撑破页面，按钮高度 ≥ 44px；深色模式下可读。

## 测试（新建 `rp_archive/tests/explore_import_test.py`，格式参照 `tests/explore_test.py`：临时库 + 末尾打印 `ALL OK`）

至少覆盖：
1. 解析：示例文本全部正确解析；全角 `｜`、`×`/`x`/`*`、`clue/item/nothing`、行首行尾空白、`\n` 换行、注释行。
2. 每一种错误都有行号：未知类型、权重越界、数量越界、线索缺标题或内容、`x` 与 `y` 只写一个、坐标越界、地点前没有地图行、掉落行前没有地点行、未注册物品、超长字段、地点超 60 / 掉落超 30。预览一次性给出多处错误。
3. 预览不写库（调用前后表行数不变）；有错误时 commit 不写库；无错误 commit 写库且单事务（用一个会在中途失败的构造验证回滚——例如让第二个地点触发写库前校验之外的失败时整体不留半截数据；做不到就至少验证「校验先于写入」）。
4. 带 `x` `y` 的新地点启用，不带的新地点停用且位置 50/50。
5. 同名处理：默认 `skip` 不动旧数据；`replace` 只改描述/图标/掉落表，**保留位置和启用状态**；线索标题相同的条目**沿用旧 `id`**（用 `explore_clues` 里已拿过的记录验证玩家不会再被发同一条线索）。
6. 物品必须注册：插件目录里有的通过、没有的被拒绝（参照 `explore_test.py` 里设置 `phone_sync` 快照 catalog 的做法）。
7. 导出再导入往返一致（含停用地点、带换行的线索、含 `|` 的内容按上面约定转成 `｜`）。
8. 次数导入：预览/应用、`默认 N`、未知角色报错、与默认相同则删除自定义、重复角色警告、数字越界。
9. 权限：未登录访问三个接口都被拒；没有 `X-CSRF` 的 POST 被拒。
