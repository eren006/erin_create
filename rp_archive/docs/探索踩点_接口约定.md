# 探索踩点 · 前端任务书（给 Codex）

后端已经写好并有测试（`rp_archive/explore.py`，`tests/explore_test.py` 全过）。**你只做两个页面模板**，后端和接口不要改：

| 文件 | 现状 | 你要做的 |
|---|---|---|
| `rp_archive/templates/explore.html` | 占位 | 玩家端：一个页面三个标签（探索 / 线索板 / 记录）+ 入口页，**手机优先** |
| `rp_archive/templates/explore_admin.html` | 占位 | 团后台配置页，手机和桌面都能用 |

只许改这两个文件（以及新建 `static/explore.css` / `static/explore.js` 也行，deploy.sh 会推 `static/` 根目录下的 js/css）。**不要改 `app.py`、`explore.py`、`phone.html` 或任何 `_phone_*.html`。**

## 它是什么

一个全新的小玩法，**不属于小手机**。玩家用和小手机同一个激活码进 `/x`；管理员在团后台「系统设置 → 探索踩点」（`/admin/explore`）配置。

玩家每天有固定次数（默认人人一样，管理员可以单独给某个人调多/少，也能额外发「临时次数」）。在地图上点一个地点 →「踩点」→ 扣一次 → 按该地点的掉落表随机掉一条：

- **线索**：进玩家的「线索板」，每人每条只会拿一次（拿过的不会再掉）
- **物品**：必须是注册过的物品，会自动进背包（机器人约半分钟内执行，所以先显示「入包中」，之后记录里变成「已入包 / 失败」）
- **空手**：什么也没找到

## 视觉要求

- **全新的风格，不要照抄小手机**（不要 iOS 分组卡片那套）。主题建议：探险/调查手账，纸张质感或夜间探照，你自己定，但要统一、好看、有一点游戏感。
- 浅色/深色都要能看（`prefers-color-scheme`），颜色全部写成 CSS 变量。
- **手机优先**：宽度 375 下不横向滚动、点击目标 ≥ 44px、`viewport-fit=cover` 并给底部安全区留白；桌面宽度居中一栏（最大 ~480px）即可。
- 不要引外部 CDN 和外部字体；图标用 emoji 或内联 SVG。
- 所有会改数据的请求都是 `fetch`，成功/失败要有明确反馈（不要只 `alert`）；请求中按钮要禁用，防连点。
- 文案全中文，语气简洁。别把需求原话当页面文案。

## 玩家端 `explore.html`

模板变量：`mode`（`entry` / `home`）、`error`（entry）、`role`、`csrf`、`enabled`（home）。

### mode == 'entry'
一个输入激活码的表单：`POST /x`，字段 `code`（10 位大写，输入框自动转大写、`autocomplete=off`）。失败时 `error` 有文案。

### mode == 'home'
页面加载后先 `GET /x/api/state`，之后不再整页刷新。顶部显示角色名、今日次数、退出按钮（`POST /x/logout`，表单带 `csrf` 字段）。

三个标签（底部固定标签栏，手机习惯）：

**① 探索**
- `enabled` 为 false（或 state.enabled 为 false）→ 只显示「探索还没有开放」。
- 有多张地图时顶部可切换（胶囊或分段）。每张地图：
  - `image` 非空 → 把图片铺满宽度（保持比例），每个地点是图上的一个标记，位置 `left:x%; top:y%`（x、y 为 0~100 的百分比），标记显示 `icon`，点按放大，名字小字跟在下面；
  - `image` 为空 → 用卡片列表展示该图的地点。
  - 图上标记多/小时在手机上也要好点，建议图下方同时给一个可点的地点列表。
- 点地点 → 底部弹出面板（bottom sheet）：地点名、描述、**今日剩余 / 临时次数**、大按钮「踩点」。次数为 0 时按钮禁用并写「今天的次数用完了」。
- 点「踩点」→ `POST /x/api/visit`，展示结果（有一点小动画/翻开的感觉）：
  - `kind=clue`：「发现线索」+ 标题 + 内容，提示「已收入线索板」；
  - `kind=item`：「获得 物品名 ×数量」，小字「入包中，稍等片刻」；
  - `kind=nothing`：「什么也没找到」+ 可选的 `text`；
  - `kind=empty`（`consumed=false`）：「这里没有新发现了」，说明没扣次数；
  - HTTP 409：次数用完；403：未开放或页面过期（提示刷新）；401：回到入口页。
  - 结果后用返回里的 `quota` 更新顶部次数，不必重新拉 state。

**② 线索板**
- `GET /x/api/clues`。以「线索板」的感觉展示：卡片墙/便签/图钉都行，每条显示标题、内容、来自哪个地点（`spot`）、时间；`new=true` 的带「新」角标。
- 进入这个标签后调用 `POST /x/api/clues/seen` 清除新标记（先渲染再清）。
- 支持按地点筛选或简单搜索（前端过滤即可）；空状态要写明「去探索看看吧」。
- 标签栏上线索数量提示：`state.clue_new` 为新线索数。

**③ 记录**
- `GET /x/api/log`：时间倒序列表，每行：时间、地点、结果标题；物品行右侧显示入包状态 `item_status`：`pending` 入包中 / `ok` 已入包 / `failed` 入包失败（提示联系管理员）；`used=bonus` 的标「临时次数」。

## 管理端 `explore_admin.html`

模板变量：`csrf`。这是团后台的页面，**顶部要引入后台统一导航**——参考同目录 `admin_places.html`：它 `{% extends "base.html" %}`，导航由 base 带出（`_admin_nav.html` 里已经加了「探索踩点」入口），你的页面也这样写，让它看起来属于后台；占位的 `explore_admin.html` 是独立 HTML，需要改成 extends 方式。页面本身手机和桌面都要可用（后台管理员也会用手机配）。

加载后 `GET /admin/explore/api/state`，所有写操作后重新拉 state（或局部更新）。分五块（顶部锚点或标签切换）：

1. **总开关与规则**：开关「开放探索」（默认关）、「默认每人每天次数」（0~99）、「每天几点刷新」（0~23，默认 0）、给玩家的一句开场说明 `intro`（≤300 字）。保存 → `POST settings`。
2. **地图**：新增/改名/删除地图（删除要二次确认，会连带删地点）；每张地图可上传背景图（`multipart`，字段 `image`，≤12MB，上传后立刻预览）。
3. **地点**：选地图后，在**图上点一下**放置/拖动地点标记（得到 x、y 百分比；也给 x/y 数字输入作为备选，因为手机上拖不准）。每个地点：名称、图标（emoji）、描述、启用开关、**掉落表**。
4. **掉落表编辑器**（每个地点一张，最多 30 行）：每行选类型：
   - `线索`：标题（≤30）+ 内容（≤600）；
   - `物品`：**只能从下拉里选注册过的物品**（`state.items` 按 group 分组，用 `<optgroup>`，**不许手填**）+ 数量（1~999）+ 可选掉落描述；`state.plugin.can_items=false` 时物品类型置灰并说明「插件版本太旧，发不出去」；`state.items` 为空时说明「还没有同步到物品清单」；
   - `空手`：可选一句话；
   - 每行有「权重」（1~1000），并实时显示该行**概率**（权重/总权重，百分比）。线索掉落提示一句：「每人每条只会拿到一次，拿完这里不再出这一条」。
   - 保存 → `POST spot`（见下），失败信息（`error`）直接显示在编辑器里。
5. **次数管理**：
   - 表格列出所有人（`state.roles`）：角色名、每天次数（自定义的标「自定义」）、今日已用/剩余、临时次数。
   - 先**多选人**（可全选），再操作：「设每天次数」（填数字，应用到选中的人）、「恢复默认」（`daily: null`）、「发放临时次数」（数量 + 备注；填负数是扣除）。
   - 说明文字：临时次数在每日次数用完后才消耗，不过期。
6. **踩点记录**：`GET /admin/explore/api/log`，最近 200 条，显示谁在哪踩了什么、物品入包状态；可按人筛选。

## 接口约定（都已实现，勿改）

所有响应是 JSON：`{ok: true, ...}` 或 `{ok: false, error: "中文原因"}`。

### 玩家端（cookie 登录，POST 必须带请求头 `X-CSRF: <模板里的 csrf>`）

| 方法 路径 | 说明 / 返回 |
|---|---|
| `GET /x/api/state` | `{enabled, role, intro, quota, maps, clue_count, clue_new}`；`enabled=false` 时只有 `{enabled:false, role}` |
| `POST /x/api/visit` body `{spot_id}` | 见下 |
| `GET /x/api/clues` | `{clues:[{id,title,text,spot,map,ts,new}]}`，新→旧 |
| `POST /x/api/clues/seen` | 把所有线索标为已读 |
| `GET /x/api/log` | `{log:[{ts,spot,kind,title,text,used,item_status}]}`，最近 60 条 |
| `GET /x/img/<name>` | 地图图片（`maps[].image` 已经是完整路径，直接用） |

`quota` = `{day, daily_limit, daily_used, daily_left, daily_custom, bonus, total}`；`total = daily_left + bonus`。
`maps` = `[{id, name, image(可为空串), spots:[{id,name,desc,icon,x,y}]}]`，只含已启用的地点。
`ts` 是毫秒时间戳；`item_status` ∈ `""`（非物品）/`pending`/`ok`/`failed`。

`POST /x/api/visit` 返回：
```
{ok:true, kind:"clue", title, text, spot, consumed:true, quota}
{ok:true, kind:"item", title:"钥匙 ×2", item:{name,qty,op_id,status:"pending"}, text(可空), consumed:true, quota}
{ok:true, kind:"nothing", title:"什么也没找到", text(可空), consumed:true, quota}
{ok:true, kind:"empty", title, text, consumed:false, quota}     // 没有新发现，没扣次数
{ok:false, error}  HTTP 409 次数用完（带 quota）/ 403 未开放或页面过期 / 404 地点不可用 / 401 未登录
```

### 管理端（团后台 session，POST 同样带 `X-CSRF: <csrf>`，body 为 JSON）

| 方法 路径 | body / 返回 |
|---|---|
| `GET /admin/explore/api/state` | `{settings:{enabled,default_daily,reset_hour,intro}, day, maps:[{id,name,image,spots:[{id,name,desc,icon,x,y,enabled,drops:[…]}]}], roles:[{role,daily_limit,custom,used_today,left_today,bonus}], items:[{group,names:[…]}], plugin:{text,can_items,has_catalog}}` |
| `POST settings` | `{enabled, default_daily, reset_hour, intro}` |
| `POST map` | `{id?, name}` → `{id}`（无 id = 新建） |
| `POST map/<id>/image` | multipart 字段 `image` → `{image}`（新地址） |
| `POST map/delete` | `{id}` |
| `POST spot` | `{id?, map_id, name, desc, icon, x, y, enabled, drops:[…]}` → `{id, drops(清洗后), warn}` |
| `POST spot/delete` | `{id}` |
| `POST quota` | `{roles:[…], daily: 数字 \| null}`（null = 恢复默认） |
| `POST bonus` | `{roles:[…], amount: 非0整数, note}`（负数 = 扣除） |
| `GET /admin/explore/api/log` | `{log:[{ts,role,spot,kind,title,used,item_status}]}` |

掉落表一行（`drops[]`）：
```
{id?, kind:"clue",    weight, title, text}
{id?, kind:"item",    weight, item, qty, text?}
{id?, kind:"nothing", weight, text?}
```
编辑已有行时**把后端给的 `id` 原样带回去**（线索去重靠它）；新增的行不带 `id`，后端会生成。删掉一行 = 不再提交那一行。
