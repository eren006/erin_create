# 踩过的坑

每条都是真实出过的问题。先看"怎么避免"，需要背景再看"经过"。

## 1. 删防刷屏导致海豹崩溃（长露谷，2026-09-09）

**避免**：用户说"把防刷屏/去重/限流删掉"时，先用一两句话讲清三件事再动手：它在挡什么、删了最坏会怎样、有没有更精准的替代。不要直接删。

**经过**：排查"农场帮助指令没反应"时，用户说先把防刷屏关掉、接着说删掉，两次都照做了。实际上那层防刷屏一直在兜底海豹平台的一个问题：同一条物理消息会被重复派发给扩展指令几十次（`rawId`/`time`/`endPoint.id` 完全相同），原来按"2 秒内同一人同一指令同参数"静默忽略，正好吃掉了重复。删掉后每次都回一条 1000 多字的长文本，几十条叠加把 WebSocket 和数据库打爆，海豹进程崩溃到打不开。之后又白白往"地牢有问题""连接重复""海豹核心 bug"这些错误方向排查，还误删了整个地牢功能。

**正确做法**：按平台侧唯一的 `msg.rawId` 去重（同一条消息重复派发才挡，玩家自己再发一次是新 `rawId`，不误伤），而不是按消息文本去重。

## 2. 排查"X 版本是好的，之后坏了"的方法

1. 先怀疑自己在这期间的改动，尤其是删除类改动，而不是先怀疑平台。
2. **尽早拿到"已知可用的版本"文件做 diff**，比任何推理都快。这次用户从头说"1.9 是好的"，却连着七八轮基于推测改代码，每轮都自称找到根因，拿到 v1.9.1 的 zip 一对比，两个主要结论全被推翻。
3. 先做一个不经过自己代码的对照实验，比如让用户测海豹内置的 `.r`，一次就能分开"平台问题"和"扩展问题"。

## 3. 指令成功但群里没反应：消息太长被静默丢掉

**避免**：单条回复控制在 **1000 字节以内**，内容多就分类或分页。给这类回复写显式的长度断言。

**看日志**：海豹发送成功会记一行「发给(群xxx): yyy」。执行成功但没有这一行，说明消息在发送环节被丢了，最常见原因就是单条太长，不是指令逻辑问题。

**经过**：`农场帮助` 拼成一条 1329 字/3192 字节的消息被平台丢弃，而其他指令回复都在 200 字节以内。mock 的 `replyToSender` 永远返回成功，所以测试里看不出来。

注：那次的诊断有过反复——曾认定"3192 字节太长"，后来 v1.9.1 里 3260 字节的帮助也能发出，说明长度不是唯一因素。所以遇到类似问题，长度是首要怀疑对象，但要用日志和 v1.9.1 对照确认，不要只凭字节数下结论。长露谷"群里收不到农场帮助"至今**未确诊**，防刷屏、包装层、消息长度、地牢都已被排除。

## 4. 单文件迭代没有版本历史

**避免**：单文件、原地快速迭代的 JS 插件，在大版本号跳变（如 1.x→2.0）之前，先确认有 git 提交或带版本号的备份副本。

**经过**：长露谷.js 从 v1.0 原地改到 v2.1.3，没有任何版本管理。用户说"1.9 是好的，回退到 1.9"时发现没有 1.9 的存档，只能从当前代码逆向删除。最终整个回退到 v1.9.1（commit 7de453c），v2.3.0 的内容保存在 42c84dc，可取回。

现在长日系统和长露谷都在 git 里，每个版本提交一次，且**只 add 相关路径**。

## 5. 改了源文件忘记同步 dist

之前编辑 `长日系统.js` 后忘了同步，diff 才发现 `core.js` 落后。两边是持续维护的镜像，不是一次性快照。**改完立刻 cp，再对 dist 那份跑 `node --check`。**

## 6. 只改了 hub 版本号，漏了 wishes

改版本号时只顾 `changri_hub.html`，`changri_wishes.html` 里独立硬编码的旧版本号已经落后好几版，被用户提醒才发现。对应清单见 `release.md`。

## 7. 误信过期的记忆

记忆里说 hub 页面部署在奥创 `static/docs`，但 `deploy_hub_pages.sh` 现在主站是贾维斯 `hub.changri.work`。涉及部署的事，**以脚本和服务器现状为准**，记忆只作线索。

## 8. async 函数里 try + 提前 return + finally → 海豹 Panic

报错形如 `Panic in auxJob-0: runtime error: index out of range [330] with length 2`。海豹的 JS 引擎（goja）在 **async 函数里 try 块中提前 `return`、同时带 `finally`** 时会崩，而且 finally 不会执行——靠 finally 释放的「进行中」标记从此卡住，后台任务悄悄停摆。自动拉取（1.7.x）和网页手机同步（1.9.0，每 30 秒一次、没新事件就提前 return，1.9.2 修）都中过。

**写法规定：** async 函数里不要用 `finally`。拆成「主体函数（可以随便 return，不写 try）」+「外层 try/catch 调主体，之后顺序释放标记」，再给标记加超时兜底。新写代码后 `grep -n finally 长日*.js` 自查。
